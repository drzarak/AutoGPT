## 2025-02-18 - SSRF Bypass via IPv4-mapped IPv6 Addresses
**Vulnerability:** The custom HTTP request wrapper used to mitigate SSRF vulnerabilities by blocking local and private IP networks could be bypassed. By using an IPv4-mapped IPv6 address (e.g., `::ffff:127.0.0.1`), an attacker could access restricted internal IPv4 addresses because the blocked IP list only checked the literal IP address object, not the underlying mapped IPv4 address.
**Learning:** Python's `ipaddress` module does not automatically apply IPv4 rules to IPv4-mapped IPv6 addresses. When an IPv6 address maps to an IPv4 address, it is technically an IPv6 object. Therefore, an `ipaddress.IPv6Address('::ffff:127.0.0.1')` does not match the `ipaddress.IPv4Network('127.0.0.0/8')` range.
**Prevention:** Always check and extract the underlying IPv4 address from IPv6 objects using the `.ipv4_mapped` property. Since the property does not exist on IPv4 objects, use `getattr(ip_addr, 'ipv4_mapped', None)` safely to extract it and apply the blocklist rules to the mapped IPv4 address instead.
