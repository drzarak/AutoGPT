## 2024-06-28 - [SSRF Bypass via IPv4-Mapped IPv6 Addresses]
**Vulnerability:** The internal SSRF protection `_is_ip_blocked` in `backend/util/request.py` failed to identify IPv4-mapped IPv6 addresses (e.g., `::ffff:127.0.0.1`) as belonging to blocked IPv4 subnets (like `127.0.0.0/8`). This would allow an attacker to bypass SSRF protections by mapping blocked internal IPv4 addresses into an IPv6 format that bypasses the simple `network in BLOCKED_IP_NETWORKS` check, since the blocklist contained IPv4 ranges and pure IPv6 ranges, but the IP address object remained an IPv6 address.
**Learning:** Python's `ipaddress` library creates `IPv6Address` objects for IPv4-mapped addresses. The `in` operator (e.g., `ip_addr in network`) does not inherently unwrap or cross-check IPv4-mapped IPv6 addresses against IPv4 network ranges. Furthermore, checking `bool(IPv4Address("0.0.0.0"))` evaluates to `False`, so `if mapped:` fails to correctly identify the mapping for the 0.0.0.0 IP, whereas `if mapped is not None:` succeeds.
**Prevention:** Always normalize incoming IP addresses before evaluating them against a blocklist. Specifically, extract the underlying IPv4 address using `getattr(ip_addr, "ipv4_mapped", None)` and check if it `is not None` before performing network containment checks.
