## 2024-06-07 - SSRF Bypass via IPv4-mapped IPv6 Addresses
**Vulnerability:** The SSRF protection in `backend.util.request.requests` relied on `ipaddress` to check resolved IPs against a blocklist. However, it failed to handle IPv4-mapped IPv6 addresses (e.g., `::ffff:127.0.0.1`), allowing an attacker to bypass IPv4 blocklists by supplying a mapped equivalent.
**Learning:** `ipaddress.ip_address()` treats `::ffff:127.0.0.1` as an IPv6 address, which will bypass any IPv4 network checks (`127.0.0.0/8`). Underlying socket connections might still resolve this to the local IPv4 address, circumventing the SSRF protection. Also, avoid fail-open logic when parsing inputs in security checks.
**Prevention:** Always check if an `ipaddress` object is IPv4-mapped (`ip_addr.version == 6 and ip_addr.ipv4_mapped`) and if so, extract the underlying IPv4 address before performing blocklist checks. Do not mask `ValueError`s from `ipaddress` with `return False` as it creates a fail-open scenario.
