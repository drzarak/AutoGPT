## 2025-02-14 - SSRF Bypass via IPv4-mapped IPv6 Addresses
**Vulnerability:** The custom HTTP request wrapper used to prevent Server-Side Request Forgery (SSRF) blocked standard IPv4 and IPv6 loopback/private addresses but failed to block IPv4-mapped IPv6 addresses (e.g., `::ffff:127.0.0.1`). This allowed an attacker to bypass the blocklist and access internal services by providing an IPv6-formatted representation of a blocked IPv4 address.
**Learning:** Python's `ipaddress` module treats IPv4 and IPv6 addresses differently. An IPv4-mapped IPv6 address is considered an IPv6 address, and checking it against a list of blocked IPv4 networks (like `127.0.0.0/8`) evaluates to false, resulting in a bypass.
**Prevention:** When implementing IP filtering or SSRF protection, always check if an IP object is an IPv6 address with an underlying IPv4 address using the `.ipv4_mapped` property. Use `getattr(ip_addr, 'ipv4_mapped', None)` securely to extract and filter the true IPv4 address before evaluating against blocklists.
