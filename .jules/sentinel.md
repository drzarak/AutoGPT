## 2025-02-23 - IPv4-mapped IPv6 SSRF Bypass
**Vulnerability:** A Server-Side Request Forgery (SSRF) bypass was found in the URL validation logic using the `requests` wrapper. The blocklist logic used `ipaddress.ip_address` to check if resolved IPs were in `BLOCKED_IP_NETWORKS`. However, an attacker could supply a hostname resolving to an IPv4-mapped IPv6 address (e.g. `::ffff:127.0.0.1`). `ipaddress` correctly parses this as an `IPv6Address`, but since the blocklist only contained native IPv4 and IPv6 loopback masks (and not the mapped IPv4-in-IPv6 equivalents), the address bypassed the blocklist checks while still reaching the internal IPv4 loopback on the host network stack.
**Learning:** `ipaddress.ip_address` treats IPv4-mapped IPv6 addresses as IPv6 types which do not overlap mathematically with IPv4 subnets like `127.0.0.0/8` in native python `ipaddress` checks.
**Prevention:** Always check for and extract the underlying IPv4 address from IPv6 objects via the `.ipv4_mapped` property before performing security or blocklist checks against network ranges.
