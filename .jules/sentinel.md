## 2024-05-24 - SSRF bypass via IPv4-mapped IPv6 addresses
**Vulnerability:** The `_is_ip_blocked` function in `backend/util/request.py` correctly checked for blocked IPv4 and IPv6 networks, but it failed to account for IPv4-mapped IPv6 addresses (e.g., `::ffff:127.0.0.1`). Python's `ipaddress` module does not automatically identify these as belonging to the underlying IPv4 network (e.g., `127.0.0.0/8`), allowing attackers to bypass SSRF protections by wrapping private IPv4 addresses in mapped IPv6 formats.
**Learning:** Checking an IP against a list of networks using `ip in network` is insufficient for complete SSRF protection because it ignores IPv4-mapped IPv6 formats, which are functionally treated as the underlying IPv4 address by networking stacks and requests libraries.
**Prevention:** Always extract and validate the underlying IPv4 address from any IPv6 address using `getattr(ip_addr, "ipv4_mapped", None)` before confirming it is safe. Add specific unit tests for `::ffff:127.0.0.1`, `::ffff:169.254.169.254`, etc.
